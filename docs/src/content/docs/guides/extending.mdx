Most users start by extracting metadata from paths or CSVs, or by adding
a domain-specific property function. Pick the extension point that
matches what you need.

## Extension map

## Rule of thumb

Prefer **hooks** before forking internals:

1. A `metadata_fn` if you need different metadata.
2. A property function if you need different features.
3. A `ModelWrapper` subclass if you need a different backbone.
4. A plugin registration when you want the extension to be discoverable
   across projects.

Only modify `phenome.pipeline` or `phenome.mixins` when none of the
above is enough; see [Architecture](/PhenoMe/guides/architecture/) for boundaries.
