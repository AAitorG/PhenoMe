Curated routes through the PhenoMe documentation and notebooks. **Pick one
path and follow it in order** - jumping around tends to leave gaps.

## Path A - First day

:::note[Goal]
Start using PhenoMe today and understand the basic concepts. Target audience:
**newcomers** with no prior PhenoMe experience.
:::

<Steps>
1. [Getting started](/PhenoMe/getting-started/) - install, verify `import phenome`, CPU/GPU note.
2. [Notebook 01 - Interactive quickstart](https://github.com/AAitorG/PhenoMe/blob/main/Notebooks/tutorials/01_interactive_quickstart.ipynb) - widgets, toy or your data.
3. [FAQ - installation](/PhenoMe/faq/#installation-and-setup) - common blockers.
4. Optional: [Core concepts](/PhenoMe/concepts/) - understand terms like visual fingerprints, metadata, and results.
</Steps>

## Path B - Your own dataset

:::note[Goal]
Run a reliable analysis on your own images using experimental info (metadata). Target
audience: **scientists / analysts** moving from a toy run to their own data.
:::

<Steps>
1. [Getting started](/PhenoMe/getting-started/) - environment locked in.
2. [Preparing your data](/PhenoMe/guides/data-setup/) - decide if you need labels; folder patterns vs spreadsheets.
3. [Notebook 02 - Load and inspect images](https://github.com/AAitorG/PhenoMe/blob/main/Notebooks/tutorials/02_inspect_your_images.ipynb) - quality checks.
4. [Notebook 03 - Core workflow](https://github.com/AAitorG/PhenoMe/blob/main/Notebooks/tutorials/03_core_phenotyping_workflow.ipynb) - embeddings, properties, plots.
5. [Select properties — Presets](/PhenoMe/guides/select-properties/presets/) — choose a `property_preset` (column meanings: [Understanding properties](/PhenoMe/concepts/property-interpretation/)).
6. [Workflows](/PhenoMe/workflows/) or [Examples gallery](/PhenoMe/examples/) - match your study design.
7. Optional: [Notebook 04 - Adding labels](https://github.com/AAitorG/PhenoMe/blob/main/Notebooks/tutorials/04_advanced_metadata_handling.ipynb).
</Steps>

## Path C - Reporting and communication

:::note[Goal]
Communicate and share your results with collaborators. Target audience: **PIs, reviewers,
authors** of a paper or slide deck.
:::

<Steps>
1. Complete **Path B** through notebook 03 (or load saved results).
2. [`PhenoMe.generate_report`](/PhenoMe/advanced/api/report/) - parameters, sections, and output.
3. [FAQ - results](/PhenoMe/faq/#results-and-interpretation).
</Steps>

## Path D - Developer / extension author

:::note[Goal]
Safe changes in the codebase and up-to-date API docs. Target audience:
**library developers** and people embedding PhenoMe in a larger pipeline.
:::

<Steps>
1. [Architecture](/PhenoMe/guides/architecture/) - packages, data flow, extension points.
2. [API & data formats](/PhenoMe/advanced/).
3. [Developer guide](/PhenoMe/guides/developer-guide/) - docstrings, Astro build, CI.
4. [Testing](/PhenoMe/guides/testing/) - ruff, mypy, interrogate.
5. [Extending PhenoMe](/PhenoMe/guides/extending/), [Plugins](/PhenoMe/guides/plugins/), [Select properties](/PhenoMe/guides/select-properties/).
6. [Notebook 06 - Plugins](https://github.com/AAitorG/PhenoMe/blob/main/Notebooks/tutorials/06_extending_phenome_plugins.ipynb).
</Steps>

## Path E - Interpretability and exploration

:::note[Goal]
Visualize patterns, find links between features, and explain AI results. Target audience: **scientists looking for biological patterns in their data.**
:::

<Steps>
1. [Notebook 05 - Exploratory analysis](https://github.com/AAitorG/PhenoMe/blob/main/Notebooks/tutorials/05_exploratory_analysis_and_explainability.ipynb).
2. [Explaining AI results](/PhenoMe/concepts/embeddings-interpretability/).
3. [Glossary](/PhenoMe/glossary/) - terminology overview (visual fingerprints, linking AI to biology, etc.).
</Steps>
